## 1. 字段清单

| 字段 | 类型 | 必填 | 格式 / 长度 | 唯一 | 可编辑 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `id` | 整数（Long） | 系统生成 | 自增主键 | 是 | 否 | 唯一辨识员工的一列，列表行与编辑路由使用 |
| `employeeNo` | 字符串 | 是 | 2-20 位，`^[A-Za-z0-9_-]+$` | 是（忽略大小写） | 否（创建后不可修改） | 工号，由用户填写 |
| `name` | 字符串 | 是 | 1-30 字符，不允许全空白 | 否 | 是 | 姓名 |
| `department` | 字符串 | 是 | 1-50 字符，不允许全空白 | 否 | 是 | 部门 |
| `position` | 字符串 | 是 | 1-50 字符，不允许全空白 | 否 | 是 | 职位（数据库列名 `job_title`，避开 SQL 关键字） |
| `hireDate` | 日期（`yyyy-MM-dd`） | 是 | ISO 日期 | 否 | 是 | 入职日期 |
| `phone` | 字符串 | 否 | 11 位中国大陆手机号 `^1[3-9]\d{9}$`；空串视为未填写 | 否 | 是 | 手机号 |
| `email` | 字符串 | 否 | `^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$`，≤100 字符；空串视为未填写 | 否 | 是 | 邮箱 |
| `gender` | 枚举 | 否 | `MALE` / `FEMALE` / `UNKNOWN`，默认 `UNKNOWN` | 否 | 是 | 性别 |
| `status` | 枚举 | 是 | `ACTIVE`（在职）/ `INACTIVE`（离职），默认 `ACTIVE` | 否 | 是 | 员工状态 |
| `createdAt` | 时间 | 系统生成 | 服务器时间（Asia/Shanghai），秒级 | — | 否 | 创建时间 |
| `updatedAt` | 时间 | 系统生成 | 同上，保存时严格递增 | — | 否 | 更新时间 |

规则：

- 字符串入库前去除首尾空白；`phone` / `email` 去除空白后为空则存 `NULL`。
- 未在表中列出的字段不得出现在请求/响应中，也不得被实现使用。
- 存储：H2（本地 `local` profile 为文件库 `./data/workbench-perf-a7`，`verify` profile 为内存库），Flyway 管理表结构，JPA 只做校验（`ddl-auto=validate`）。

## 2. 接口约定

统一前缀 `/api`，请求与响应均为 JSON，无鉴权（原始需求未提出）。

### 2.1 成功响应

```json
{ "success": true, "data": <数据体> }
```

### 2.2 失败响应

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "工号不能为空",
    "fieldErrors": [{ "field": "employeeNo", "message": "工号不能为空" }]
  }
}
```

`code` 是稳定的错误类别，前端据此区分提示；`message` 是人类可读消息；`fieldErrors` 仅在字段级错误时出现。

### 2.3 接口列表

| 用途 | 方法 | 路径 | 成功状态 | 数据体 |
| --- | --- | --- | --- | --- |
| 列表（EMP-01） | GET | `/api/employees` | 200 | `Employee[]`，按 `id` 升序 |
| 编辑回填（EMP-03 辅助读取） | GET | `/api/employees/{id}` | 200 | `Employee` |
| 新增（EMP-02） | POST | `/api/employees` | 201 | 新建的 `Employee` |
| 编辑（EMP-03） | PUT | `/api/employees/{id}` | 200 | 更新后的 `Employee` |

`Employee` 结构：

```json
{
  "id": 1,
  "employeeNo": "E1001",
  "name": "张三",
  "department": "研发部",
  "position": "后端工程师",
  "hireDate": "2024-01-31",
  "phone": "13800138000",
  "email": "zhangsan@example.com",
  "gender": "MALE",
  "status": "ACTIVE",
  "createdAt": "2026-11-08T22:30:00",
  "updatedAt": "2026-11-08T22:30:00"
}
```

新增/编辑请求体：字段清单中除 `id`、`createdAt`、`updatedAt` 外的全部字段。编辑时 `employeeNo` 必须与当前值一致（忽略大小写），否则返回校验错误，**不会**把编辑当作新增处理。

列表不做分页、搜索、排序（原始需求未确认），后端不接收相关参数，也不提供删除/批量接口。

## 3. 错误语义

| 场景 | HTTP | `code` | 触发示例 | 前端表现 |
| --- | --- | --- | --- | --- |
| 参数校验失败 | 400 | `VALIDATION_ERROR` | 必填为空、工号格式、手机号/邮箱格式、日期格式、枚举越界、编辑时修改工号 | 表单内逐项校验并拦截提交；服务端返回时表单顶部展示错误详情，输入保留 |
| 唯一性冲突 | 409 | `DUPLICATE_EMPLOYEE_NO` | 工号（忽略大小写）已存在 | 表单顶部独立提示"工号已存在"，表单不关闭、输入不丢失 |
| 目标记录不存在 | 404 | `EMPLOYEE_NOT_FOUND` | 编辑的 `id` 不存在 | 提示"员工记录不存在"，不新建记录 |
| 服务端/持久化异常 | 500 | `INTERNAL_ERROR` | 未预期异常 | 提示"保存失败，请稍后重试"，表单保留 |
| 资源不存在 | 404 | `NOT_FOUND` | 未知路径 | — |
| 方法不支持 | 405 | `METHOD_NOT_ALLOWED` | 对员工接口发 DELETE | 列表不暴露删除入口 |

## 4. 双端校验一致性

前端规则定义在 `frontend/src/views/EmployeeFormView.vue` 的 `rules`，后端规则定义在 `EmployeeRequest`（Bean Validation）与 `EmployeeService`（归一化、唯一性、工号不可修改）。两边对同一字段使用完全相同的正则与语义：

| 字段 | 前端规则 | 后端规则 |
| --- | --- | --- |
| `employeeNo` | required + `^[A-Za-z0-9_-]{2,20}$` | `@NotBlank` + `^$|^[A-Za-z0-9_-]{2,20}$`（空串交给 `@NotBlank` 报"不能为空"） |
| `name` / `department` / `position` | required + 最大长度（30/50/50） | `@NotBlank` + `@Size(max=...)` |
| `hireDate` | required，日期选择器输出 `yyyy-MM-dd` | `@NotNull` + `LocalDate` 反序列化（格式错误映射到 `hireDate`） |
| `phone` | `^$|^1[3-9]\d{9}$` | 同左 |
| `email` | `^$|^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$` + 最大 100 | 同左 |
| `gender` | 下拉固定三个取值 | 枚举反序列化，越界映射到 `gender` |
| `status` | 下拉固定两个取值 + required | `@NotNull` + 枚举反序列化，越界映射到 `status` |

服务端为最终权威：任何绕过前端的非法请求都由后端拒绝并返回相同语义的错误。
